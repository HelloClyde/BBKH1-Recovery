# 使用说明

适用：Windows x64 与已确认的 H1 V1.41 超级系统恢复流程。此程序可以擦写 H1 系统。

1. 从版本 Release 下载完整 ZIP，全部解压到可写目录。不要直接在 ZIP 内运行。
2. 保持 H1 供电与 USB 连接，按住 Shift，轻点 RESET，再松开 Shift，进入 USB Boot。
3. 双击解压目录中的 `启动恢复.cmd`。按 Windows 正常提示允许管理员操作。
4. 入口会校验全部恢复文件，在当前目录的 `H1RecoveryV141` 内部署，并自动准备 USB Boot 与 BURN 两组 WinUSB 驱动，然后打开官方恢复界面。
5. 等待恢复结束与 H1 正常启动。恢复过程中不要拔线、复位或再次运行入口。

不需要单独打开 Zadig。驱动操作仅匹配 `601A:4740` 与 `0888:A880`；正常 USB 磁盘模式的设备身份不在此绑定范围内。管理员权限仍由 Windows 控制，脚本不会绕过 UAC。

## 目录与退出

- 所有程序文件默认留在解压目录内，不安装到 ProgramData。
- `H1RecoveryV141/BACK_UP`、`BACK_UP2` 是官方程序可能生成的用户资料备份。发生异常时先保留它们。
- `backups/` 保存被一键准备程序替换的电脑文件，与官方用户资料备份不同。
- 软件用完并结束恢复后，可删除整个解压目录；Windows 已安装的驱动由系统单独管理，不随删除目录卸载。
- 单纯进入 USB Boot 而没有运行恢复时，通常可松开所有按键后轻点 RESET 正常启动。已经开始擦写或出现失败时，先保留窗口、日志和连接，核对当前阶段后再操作。

## 核对和日志

- `仅校验文件.cmd`：核对完整包及显示执行计划；不装驱动、不启动恢复、不访问 H1。
- `打开日志.cmd`：打开 `H1RecoveryV141/H1USBBridge.log`。
- `installation-result.txt`：记录部署与驱动准备结果。
- 入口发现恢复程序已经运行时会停止，不替换文件或重复开程序。

首次部署需要约 1 GB 的恢复数据空间，另留备份和运行空间。100% 进度条不代表后续用户资料恢复与结束命令必然完成；以最终状态及设备正常启动为准。

## 0% 与日期报错

0.2.2 包含首次 BURN 枚举稳定等待，以及备份属性两位格式修正。后者处理 `Invalid argument to date encode`：额外文件属性曾导致日期字段错位。

如果仍然报错，保留 `BACK_UP`、日志及窗口文字，注明所用版本和设备系统版本。不要反复重刷，也不要用空文件替换备份。曾使用的私有两文件续接程序不在公开包内，它只针对当时已核对的文件和设备会话。

## 手动替换兼容层

开发者可将兼容层单独包中的 `WDAPI901.DLL` 放到官方 `super_recover.exe` 同目录，先备份已有 DLL。该 DLL 是 x86，与官方程序同架构；电脑上的 USB 驱动是 WinUSB。单独包不包含完整恢复内容和驱动自动安装入口。
